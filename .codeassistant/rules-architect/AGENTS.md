# Project Architecture Rules (Non-Obvious Only)

- Единственная runtime-зависимость — Express 4; статика, CORS, security headers, problem+json и лимитер реализованы вручную, чтобы не тянуть helmet/cors/express-rate-limit.
- Сервер stateless, но лимитер живёт в памяти процесса: при нескольких инстансах или за балансировщиком нужен общий стор, иначе лимит умножается на число процессов.
- UI и API используют один изоморфный генератор, но UI не ходит в API: офлайн-генерация и отсутствие передачи паролей — архитектурное требование, не дублирование ради дублирования.
- Граница изоморфности — каталог `shared/`: любой Node-импорт там ломает браузер, а браузерный API ломает тесты.
- `openapi.json` — контракт; тест фиксирует только список путей и наличие `operationId`, поэтому схемы могут разойтись с кодом без падения тестов.
- Service worker кеширует оболочку по версии и намеренно исключает `/api/`; изменение стратегии кеширования затрагивает приватность (пароли не должны попадать в Cache Storage).
- CSP запрещает inline-скрипты и стили; подключение UI-библиотеки, требующей inline, потребует пересмотра политики и объяснения в документации.
- Персистентности нет по дизайну: добавление истории паролей — это решение о хранении секретов и отдельный privacy-анализ, а не «недостающая фича».
- Генерация детерминированно гарантирует по символу каждой категории и использует криптостойкий RNG; возврат к `Math.random()` или рекурсивному перебору недопустим.
